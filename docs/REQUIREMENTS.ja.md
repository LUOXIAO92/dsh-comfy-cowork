# DSH Comfy Cowork 製品要件

- バージョン：v1.0（確定）。本書は v1.0 の動作を説明します。

## 1. 製品の位置づけ

DSH Comfy Cowork は DSH に組み込むプラグインで、画像編集キャンバス、ComfyUI ワークフローブラウザ、agent との協働を 1 つの画面にまとめます。チャットは左、キャンバスは右にあり、人と agent が同じキャンバス状態で作業します。

1. **キャンバスは共有状態**であり、チャットの添付ファイルではありません。人が描いたマスク、引いた枠、書いたプロンプトを agent が読めます。agent が書いたプロンプトは、人がテキスト欄で見てそのまま編集を続けられます。
2. **成果物はそのまま ComfyUI に入ります**。マスクは ComfyUI が読める PNG、プロンプトは MOSS-Image がそのまま使える文字列、ワークフローは ComfyUI 自身が保存した JSON です。
3. **ローカル優先**。画像は本機、DSH、ユーザーが設定した ComfyUI の間だけを流れます。

プラグインはセッション単位で有効になります。インストール直後はデフォルトで休眠状態です。あるチャットで `/dsh-comfy-cowork`（メニュー行の表示名は `DSH Comfy cowork`）を実行して初めてキャンバスが開き、`comfy_coworking_*` ツールがそのセッションの agent に接続されます。キャンバスのタブを閉じるとこれらのツールは外れます。オン/オフの状態はドキュメントに保存され、更新や再起動の後も維持されます。他のチャットからはこれらのツールは見えません。

## 2. 機能範囲

画像モード：画像の読み込み、ズーム/パン/ウィンドウに合わせる、ブラシ/消しゴム/矩形/楕円マスク、元に戻す/やり直す、マスク演算、書き出し。

レイアウトモード（MOSS-Image のみ）：キャンバスサイズの設定、枠の描画とドラッグ/リサイズ、枠ごとの `label`/`caption`/`text`/`palette`/`tags` 編集、レイアウトプロンプトのリアルタイムコンパイル、サイズと枠の検証。

プロンプト：ポジティブ用のテキスト欄が 1 つ、ネガティブ用が 1 つ。手入力、agent ツールによる書き込み、レイアウトコンパイル結果はすべて同じ `prompt` フィールドに入ります。ネガティブプロンプトは別に保存され、実行時にサンプラーに接続された negative テキストノードへ書き込まれます。

コメント：画像上で枠を引いて注釈を書き、作者（`user` / `agent`）を記録します。注釈はドキュメントに保存され、書き出した PNG にも埋め込まれます。agent が注釈を読むときは、その領域のスクリーンショットも同時に受け取ります。

ワークフロー：ComfyUI の `userdata/workflows` とローカル JSON を一覧・読み込みします。ノードグラフ、パラメータ、タイトル、bypass/mute の編集、サーバーへの保存または書き出し、注入バインディング、キュー実行、キャンセル、結果のキャンバス反映。モデル一覧は ComfyUI の `/models`、`/models/{folder}`、`object_info` の combo から取得し、ノード内のモデル選択はそのまま操作できます。

永続化：セッションごとのワークスペースディレクトリ `.comfy-cowork/<sessionId>/` に、`document.json`、画像とマスクのアセット、`runs/` を置きます。書き込みはアトミックで、更新や再起動の後に復元されます。

初版ではやらないこと：動画編集 UI（タイムライン、マルチトラック、カット編集）。ノードの任意追加・削除や再接続。Comfy Cloud と複数サーバーのアカウント。モデルのダウンロード・削除・ディレクトリ管理。複数人でのリアルタイム共同編集。内蔵の切り抜き・深度・姿勢などのスマートマスク（ComfyUI ノードに任せます）。

## 3. キャンバスとマスク

- マスクの意味：白/不透明 = 編集可能な領域。「反転」スイッチを用意します。
- ブラシ：サイズ 1–400 px（元画像のピクセル基準）、硬さ 0–100%、不透明度 1–100%。`[` `]` でサイズを変更し、`Alt` で一時的に消しゴムに切り替わります。
- 図形：矩形、楕円。ドラッグで作成し、`Shift` で正方形/円に制約、作成後は元に戻せます。
- マスク演算：先に拡張/収縮（−128–128 px）、次にぼかし（0–128 px のガウスぼかし）。クリアも可能。プレビューは赤または選択した色で重ね、透明度を調整できます。非表示にして元画像だけを見ることもできます。
- 書き出し：`mask.png`（グレースケール、白 = 編集領域）と `canvas_rgba.png`（元画像の RGB + alpha = マスク）。ComfyUI の `LoadImage` は alpha から mask を取得し、`LoadImageMask` はカラーチャネルから mask を取得します。両方のファイルを用意し、ワークフローのバインディングで選択します。

## 4. MOSS-Image レイアウト

ComfyUI 0.41.0 の実際のインターフェース：ノード `MOSSImageLayoutPrompt` は `prompt`、`element`、`width`、`height`、`character_boxes` を受け取り、1 行の JSON を出力します：

```json
{
  "summary": { "caption": "<全体の説明>" },
  "items": [
    { "label": "object", "caption": "...", "bbox": [y1-H/2, x1-W/2, y2-H/2, x2-W/2] }
  ],
  "bbox_coord_space": "abs_centralized",
  "bbox_format": "yxyx"
}
```

- 枠の座標はまず 0–1000 に正規化し、次にピクセルに変換します：`floor(y1*H/1000)-H//2`、`floor(x1*W/1000)-W//2`、`ceil(y2*H/1000)-H//2`、`ceil(x2*W/1000)-W//2`。コンパイルは Python ノードの丸め規則とバイト単位で一致します。
- `text` タイプの item は `"text"` を追加で持ちます。パレットがある場合は `"palette"` を持ち、色は最大 5 つです。
- `CreateBoundingBoxes` の `bboxes` は JSON 文字列を受け取ります：`[{type:"obj"|"text", bbox:[ymin,xmin,ymax,xmax] (0–1000), text?, desc?, color_palette?}]`。
- 枠がない場合、テキスト欄には通常の caption を入れ、JSON では包みません。枠がある場合はコンパイル済みの 1 行 JSON を入れます。
- キャンバスサイズ（16 の倍数）、枠のはみ出し、負の幅/高さ、`text` タイプの空テキストを検証します。検証に失敗するとパネルにエラーが表示され、プロンプトは直前の有効な内容を保持します。

## 5. プロンプトの単一ソース

`document.prompt` が唯一の正式なプロンプトです。書き込み経路は 3 つだけです：ユーザーがテキスト欄に入力する、レイアウト変更後に自動コンパイルする、agent がプロンプトツールを呼ぶ。

- agent のプロンプトツールは `document.prompt` だけを書き込みます（および構造化された summary と枠ごとの caption）。結果として最終テキストを返し、チャットにだけ書くことは許されません。ユーザーが入力中のとき、agent の更新はフォーカスを奪いません。「agent が更新しました」というヒントを表示し、ユーザーが読み込む形にします。
- すべての書き込みに `rev` が付きます。ワークフロー実行時にはテキスト欄の現在の内容を注入します。ユーザーが手で変更したコンパイル結果はユーザーのバージョンとして送信し、再コンパイルで上書きしません。

## 6. ComfyUI 互換

- HTTP プレフィックスは `/api/comfy-cowork`。デフォルトでは `http://127.0.0.1:8188` に接続し、DSH Host がプロキシします。ブラウザは直接接続しません。`Origin: http://127.0.0.1:3080` 付きで ComfyUI に直接接続すると 403 が返るため、Host プロキシが必須の経路です。使用するインターフェース：`system_stats`、`models`、`models/{folder}`、`object_info`、`userdata`（workflows の読み書き削除）、`upload/image`、`prompt`、`history/{prompt_id}`、`queue`、`interrupt`、`view`。
- プロンプトテキスト、キャンバス画像、マスク、キャンバスの幅/高さ、シードをバインディングに従って注入します。実行前にローカル検証（必須入力、ノードの存在、型の一致）を行ってから `/prompt` に送信します。

ワークフロー変換の対象：widget パラメータ、接続、`Reroute`、`Primitive`、`Note`、bypass（mode 4）、mute（mode 2）、seed の `control_after_generate` 追加 widget。API 形式のワークフローはそのまま使用します。subgraph や未知のカスタムノードに遭遇した場合は明確にエラーを出し、該当ノードを示します。ノードを黙って落とすことはありません。

バインディングはワークフローごとに保存され、`document.workflow.bindings` に書かれます。一致するノードがない場合はワークフローだけを実行でき、結果にどのロールが注入されなかったかを示します。

| ロール | 注入する内容 | 自動推論 |
|---|---|---|
| prompt | プロンプトテキスト欄の内容 | `CLIPTextEncode` のタイトルに positive/プロンプトを含む。MOSS layout ノード |
| image | キャンバス元画像のアップロード名 | `LoadImage` の最初のもの |
| mask | RGBA 画像または独立マスク | `LoadImage` の mask 出力 / `LoadImageMask` |
| width/height | キャンバスサイズ | `Empty*LatentImage` / `MOSSImageLayoutPrompt` |

## 7. Agent ツール

ツールは共通のプレフィックス `comfy_coworking_` を持ち、すべて Host のセッションドキュメントを介して動作します：

- 読み取り：`state`（キャンバス、枠、プロンプト、バインディング、最近の実行、アセットのパス）、`health`（接続と診断）。
- プロンプトとレイアウト：`set_prompt`、`set_layout`、`upsert_box`、`remove_box`。
- キャンバス：`load_image`（ワークスペース内のパスに限る）、`set_canvas`。
- ワークフローとモデル：`list_workflows`、`load_workflow`、`list_models`、`bind_workflow`。
- 実行：`run`、`run_status`、`interrupt`。
- 注釈：`comments`（一覧、追加、更新、削除。領域のスクリーンショットのパスを返す）。
- パネル：`open_canvas`（開いているフロントエンドのページでキャンバスタブを開く）。

Host のシステムプロンプトでは、画像生成に関するプロンプトは必ずこれらのツールを通してテキスト欄に書くよう求めています。`state` はキャンバスとマスクの絶対パスを返し、agent は画像読み取りツールで確認します。ツールの結果ごとに大きな画像を詰め込まないためです。

## 8. 非機能要件

- テーマ：`--dsw-alias-*` token のみを使用し、ダークとライトのどちらでも読めます。UI 文言はすべて locale を経由し、中国語、英語、日本語を用意します。その他の言語は英語にフォールバックします。
- 性能：表示にはサムネイル、マスクと書き出しには元画像のピクセルを使用します。`object_info` はキャッシュし、手動更新も可能です。ドキュメントの変更は SSE で通知します。実行状態は 1 秒ごとにポーリングします。
- 信頼性：ドキュメントはアトミック書き込み（一時ファイル + rename）です。ドキュメントが壊れた場合はバックアップして再構築します。ComfyUI が切断されてもキャンバスは編集できます。実行に失敗した場合はエラーとノード id を保持します。テレメトリはなく、画像はユーザーが設定した ComfyUI にのみ送ります。ログはデフォルトでプロンプト全文を出力しません。
- テスト：38 個の `node:test` 単体テストがあり、MOSS コンパイル、ワークフロー変換、ドキュメント保存と旧ディレクトリ移行、HTTP ルートをカバーします。実際の ComfyUI で画像生成を手動検証済みです（MOSS テキストからの生成、MOSS レイアウト、SDXL inpaint）。

## 9. 確定済みの決定事項

- ワークフロー編集の深さ：閲覧、パラメータ/タイトル/bypass の変更、保存。ノードの任意追加・削除や再接続は行いません。
- パネルの位置：右サイドバーのタブ。チャットと並び、全画面も可能です。
- デフォルトのワークフロー：テンプレートを内蔵せず、ComfyUI サーバーから読み込みます。`moss_template.json`、`coworking_smoke.json`、`coworking_inpaint.json`、`coworking_moss_layout.json` で互換性を検証します。
- 部分編集：汎用ワークフローにバインディングを加えます。SDXL の `VAEEncodeForInpaint` 経路は検証済みです。
- agent の能力：キャンバスとプロンプトの読み書き、枠の編集、ワークフローの実行、結果の確認。実行は可視で、キャンセル可能です。
- MOSS プロンプトの形：テキスト欄には最終的にコンパイルされた 1 行の layout JSON を入れ、summary と枠ごとの caption は横の編集エリアで変更します。
- 動画：動画編集 UI は作りません。既存の動画ワークフローは読み込み、実行、出力のプレビューができます。

## 10. 既知の制限

- サブグラフのワークフローは未対応で、明確にエラーになります。API 形式のワークフローは実行と保存ができますが、グラフ表示は読み取り専用です。
- ComfyUI サーバーは 1 台のみです。
- agent の `open_canvas` は、すでに開いているフロントエンドのページでタブを開くだけです。ページが開いていない場合は開きません。
- 動画は汎用ワークフローの実行と `<video>` プレビューのみで、タイムラインはありません。
- ブラウザ内では元画像の解像度でマスクを処理します。4K 以上の画像は先に縮小してください。
